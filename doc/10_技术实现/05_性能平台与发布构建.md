# 性能平台与发布构建

按 **Windows + Godot 4 .NET + C#** 建立原型开发环境。必需组件是 Godot .NET 编辑器和 .NET SDK；外部代码编辑器用于日常开发，匹配版本的 .NET 导出模板用于打包游戏。正式发布平台与性能指标仍待确认。

[返回游戏概览](../00_游戏概览.md)

技术取舍与平台限制以[技术选型与架构](01_技术选型与架构.md)为准。本页是安装和构建方案，不代表已经检查过本机组件或完成过项目构建。

## 必要组件与安装选择

| 组件 | 必要程度 | 选择与用途 |
| --- | --- | --- |
| Godot 4 .NET 编辑器 | C# 开发必装 | 从官网下载标有 .NET / C# support 的稳定版，完整解压运行；普通版不提供 C# 开发支持 |
| .NET SDK | C# 编译必装 | 当前建议 .NET 10 稳定 SDK；结合所选 Godot 版本与项目 TargetFramework 验证后锁定，不能只安装 Runtime |
| VS Code + 微软 C# 扩展 | 日常开发强烈建议 | 提供补全和调试；也可使用已有 Visual Studio 或 Rider，编辑器之间任选其一 |
| .NET Export Templates | 导出游戏必装 | 必须与 Godot 编辑器版本完全一致，选择支持 C# 的模板 |
| Git | 建议 | 管理代码、配置、文本场景和项目文件；大型二进制资源按需采用 Git LFS |

普通 Intel/AMD Windows 电脑使用 x64 编辑器与 x64 SDK；ARM 设备采用与自身架构匹配的版本。Godot 可直接解压运行；SDK 需单独安装，或由兼容版本的 Visual Studio 提供。使用 Visual Studio 时选择“.NET 桌面开发”工作负载，并确认所需 SDK 已安装。

Godot 只负责编辑器及运行所需部分，C# 编译工具由 .NET SDK 提供。NuGet 依赖通过项目引用和还原管理；xUnit 在测试项目建立后加入，不是先行安装的桌面软件。美术工具、第三方插件和其他平台 SDK 随实际需求添加。

## 安装后的验证步骤

1. 在 PowerShell 执行 `dotnet --list-sdks`，确认能够找到所选 SDK；记录实际版本。
2. 打开 Godot .NET 编辑器，在“编辑器设置 → Dotnet → Editor”中选择外部编辑器。VS Code 安装微软 C# 扩展；调试任务按官方说明配置。
3. 创建最小项目，为节点附加 C# 脚本并构建运行。确认生成的项目文件、TargetFramework 与所选 SDK 匹配，NuGet 依赖能够还原。
4. 在“编辑器 → 管理导出模板”中安装同版本 .NET 模板，再在“项目 → 导出”中添加 Windows 预设。
5. 导出并在无 Godot 和 .NET SDK 的测试设备运行，检查启动、资源加载、中文显示及存档读写。

以上均为待执行步骤；首次环境验证通过后填写下表，并将版本约束加入实际工程文件。

| 项目 | 当前选择 | 尚需登记 |
| --- | --- | --- |
| Godot | 4.x 稳定版 .NET | 准确补丁版本与架构 |
| .NET SDK | 推荐 10.x 稳定版 | 验证后的准确 SDK 版本、global.json 策略 |
| 目标框架 | 与选定 Godot 版本兼容 | 项目实际 TargetFramework |
| 导出模板 | 与 Godot 完全同版本的 .NET 模板 | 安装版本及 Windows 预设名称 |
| 测试依赖 | xUnit | 验证后的包版本与项目引用 |

## 构建与版本管理

工程建立后，将 Godot 项目文件、C# 项目文件、源代码、JSON 配置、文本场景及适合共享的导出预设纳入 Git。将 `.godot/`、C# 的 `bin/` 和 `obj/`、独立构建产物目录作为生成内容管理；机器路径与发布凭据不进入共享预设。

日常验证顺序为：依赖还原与编译 → 配置校验与规则测试 → Godot 场景检查 → 目标平台导出 → 独立运行。`dotnet build`、`dotnet test` 的准确项目路径、Godot 导出命令、预设名及产物目录在工程建立后补齐，不将占位命令当作已可执行构建流程。

开发版保留规则日志与调试面板；发行版关闭作弊入口，并记录程序版本、配置版本和存档结构版本。具体开关与日志保留策略待实现。验证前后记录仓库状态，只清理由本次验证生成且归属明确的产物。

## 性能与平台验收

原型优先测量视野重算、卡牌动画、长效果连锁、大背包和跨区域加载。使用 Godot 性能工具观察场景表现，C# 规则层记录结算耗时并通过模拟器复现；具体工具配置与测试设备在原型建立后登记。

| 验证内容 | 验收方向 | 待定参数／状态 |
| --- | --- | --- |
| 最低设备与运行预算 | 在明确目标设备上测量帧率、内存与加载耗时 | 设备、预算均待定；未验证 |
| 内容规模压力 | 多状态、长连锁、大手牌与背包仍能完成交互与结算 | 规模上限待定；未验证 |
| 窗口与输入 | 分辨率缩放后文字和手牌可读，输入焦点可恢复 | 输入方式、分辨率与失焦策略待定 |
| 平台存储 | 使用平台适合的用户数据目录，安装目录只读时仍可存档 | 路径实现待定；未验证 |
| 独立构建 | 完整导出包在无开发环境的设备运行 | 未验证 |
| 更新与恢复 | 旧档迁移失败不覆盖原文件，可识别不支持的版本 | 见存档方案；未验证 |

发布前执行安装、启动、资源加载、存档升级和卸载相关检查；程序与配置回退须同时检查存档兼容性。第三方代码和素材分别记录来源、许可与署名要求。具体发布渠道、自动构建服务、签名及更新方式待确定。
