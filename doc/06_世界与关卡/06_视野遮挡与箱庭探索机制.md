# 视野遮挡与箱庭探索机制

> 状态：有限视野与遮挡要求已确认；具体探索机制为建议草案 ｜ 更新日期：2026-10-09 ｜ 实现与试玩：完整方案未进行

**已确认要求：探索保持有限可视范围，范围外保留神秘感；关闭的房门后、拐角遮挡处不可直接看见。** 用户指定继续参考《黑暗之魂》三部曲的探索体验。本页建议用“局部观察—试探前进—建立空间记忆—打开捷径—回访或深入”组织箱庭探索，让玩家逐步理解区域，而不是一次获得完整信息。

第 1 节明确确认边界；其余为适配本项目的建议，具体半径、提示时机、路线规模和资源数值通过原型验证。既有属性、装备供牌和角色回合规则继续有效。

## 1. 已确认的视野边界

- 玩家只能直接观察当前可视范围内的信息；范围外的空间与内容保持未知或不可实时观察。
- 实体墙、关闭的房门和拐角形成遮挡。即使位置处于屏幕内，也不能直接看见遮挡后的房间内容。
- 探索过程中通过移动、开门和改变观察位置逐步获得信息。

下文的全周视野、地形记忆、声音线索与提示方式，是落实这些边界的推荐方式；用户尚未指定具体视野形状、范围或照明机制。

## 3. 视野、遮挡与地图记忆

### 可视范围

在当前俯视角移动草案下，推荐角色周围全周的有限视野。角色转向不需要额外操作镜头；视野距离、遮挡物和所在楼层共同决定能看到什么。原型先固定基础范围，照明与环境变化后续再扩展。

| 空间情况 | 推荐表现 |
| --- | --- |
| 完整墙体、关闭的不透明门 | 截断视线；隐藏另一侧的敌人、物品、房间地面与提示 |
| 房门打开 | 仅揭示通过门洞实际能看到的部分，墙侧死角继续遮挡 |
| L 形走廊或柱子背后 | 随角色位置逐渐揭示，拐弯不一次揭开整条走廊 |
| 窗口、栅栏、低矮障碍 | 按明确的透视属性露出局部景象；可见不代表可通行 |
| 超出视距的开阔空间 | 逐渐隐去实时细节；视野边缘的过渡效果不能泄露对象轮廓 |
| 楼梯、上下层、升降机 | 各层单独判定；重叠在屏幕上的楼层不会相互透视；观景开口只显示实际可见部分 |

门的开合会立即改变遮挡。屋顶或前景墙为方便操作而淡出时，后面的内容仍受视野限制。移动镜头、缩放地图、悬停鼠标也不能扩展角色视野。

当前美术暂定为暗黑氛围与简约像素风，具体原则见[美术风格与资源清单](../09_美术音频与文本/01_美术风格与资源清单.md)。视觉明暗与逻辑遮挡分别处理：可见空间保持路径和物件辨识度，光效、轮廓及亮度设置遵守相同的可见性边界。

### 三种信息状态

| 状态 | 场景与地图表现 | 信息边界 |
| --- | --- | --- |
| 未探索 | 遮蔽具体地形，只显示已经能够观察到的边界 | 不预先标出房间形状、隐藏门、敌人、宝箱或出口 |
| 当前可见 | 显示实际可见的场景和对象 | 只提供可观察或已知信息，看见一个怪物不揭示同队未露面的成员 |
| 曾见但当前不可见 | 保留低亮度的地形记忆、已确认地标与玩家标记 | 隐藏动态敌人、血条、物品光效和实时门状态；记录表示上次观察，不是实时监控 |

地形记忆只覆盖曾经实际看见的范围。通过栅栏看到的走廊可以留下记忆，但不会自动记录到达路线、激活传送点或确认跨区域连接。NPC 提供的传闻可以作为文字笔记，不直接揭开其指向的房间。

建议默认提供按需打开的探索地图，保留手动标记；常驻小地图是否需要由试玩决定。地图不预绘完整房间、不显示剩余宝箱数量或全区域完成百分比，帮助玩家保留“也许还有地方没发现”的判断空间。

### 界面与声音的一致性

敌人轮廓、名称、交互提示、目标选择、鼠标悬停、掉落光效与小地图标记共用可见性边界。已经认识某类敌人，可以查阅已有知识，但无法据此追踪当前墙后的个体。

声音可以传递模糊线索，例如门后脚步、远处铁链、流水或呼吸；不直接报告敌人数量、精确坐标或奖励品质。门缝的光可以照到玩家这一侧，但不揭开门后实体。声音与光线应符合实际场景，静默也不保证安全。

可访问性提示采用同样精度的文字，如“门后传来拖拽声”。提示不依赖精确立体声辨位，也不额外揭示隐藏对象。

## 4. 把区域设计成逐步理解的空间

### 稳定布局与局部回路

推荐主地形、关键门和捷径采用固定设计，让玩家能记住地标、判断相对位置，并在回访时验证自己的理解。随机奖励或遭遇变体可以后续评估；休息或死亡时保留主路径关系。

一个探索段落围绕可辨认的地标组织：从安全位置进入未知通道，经过遮挡和局部岔路到达新的观察点，再从另一侧打开回到熟悉地点的连接。具体回路数量按区域体量确定；区域间仍维持既有的简单网状关系。

| 路径与空间 | 设计职责 |
| --- | --- |
| 推进路线 | 通向新地标、关键挑战或跨区域入口，提供逐步深入的方向 |
| 局部绕行 | 在战斗风险、路程和信息获取之间提供实际取舍 |
| 可选支路 | 以装备、交互、短叙事或观察点回报主动探索 |
| 观察窗口／高台 | 让玩家在真实视线内看到暂时到不了的位置，形成寻找路线的目标 |
| 回接捷径 | 从深处返回已知位置，降低后续探索与失败重试的负担 |

地标通过形状、材料、光色、环境声或独特物件区分。远处地标只有处于真实视线内才可见；路线引导使用玩家能观察到的线索，界面不提前标出完整路径。

### 门、钥匙与捷径的不同职责

| 类型 | 玩家最初获得的信息 | 如何改变后续探索 |
| --- | --- | --- |
| 普通遮挡门 | 门本身及可能的声光线索，内部未知 | 开门后增加局部可见空间；开门与进入分开 |
| 需要钥匙的门 | 检查后得知锁具或铭文线索 | 获得钥匙后形成明确的回访目标，仍需到门前使用 |
| 从另一侧开启的捷径门 | 近侧无法开启，具体门后关系尚不确定 | 从深处解锁后建立稳定回路；力量检定不绕过这类结构条件 |
| 卡住的可选侧门 | 明确提示可用力量或其他解法处理 | 延续属性便利方案，承担局部绕行选择 |
| 升降机、梯子、桥梁 | 可见结构与当前状态 | 从可达端启用后缩短路径；调用或通行前显示本侧可确认的信息 |
| 秘密入口 | 存在局部可观察的异常线索 | 通过检查或机关揭示可选空间；不要求玩家逐面墙盲试 |

钥匙提示可以帮助联想已检查的门，但不会为尚未发现的门生成地图标记。隐藏入口通过材质接缝、地面痕迹、物件摆放或短留言提供线索；必经入口需要足够明确的发现过程。

## 5. 保留未知风险，同时让卡牌战斗可准备

建议将明雷理解为“敌人具有场景实体，进入视线后才显现”。门后或拐角处可以安排敌人；声音、脚印、破损物件等线索让玩家推测风险，具体编组和打法仍可能在进入战斗后才明确。

普通接敌推荐遵循以下过程：

1. 在遮挡边缘观察线索，选择开门、换位置观察或暂时离开。
2. 开门或走过拐角后逐步看到敌人，保留辨认与后退空间；开门操作本身不触发普通战斗。
3. 玩家继续接近，或已显现的接触型敌人完成预警后接近，达到有效接触条件开始战斗。启用远程接战的怪物则需持续保持有效射线并完成明确瞄准，详见[远程开战方案](08_远程怪物行为与开战.md)。
4. 战斗期间冻结地图，按本场遭遇进入卡牌结算；探索揭示、移动或等待均不触发战斗回合。

布局需要把普通接触触发区放在玩家能够先观察到的位置，试玩验证最高允许移动速度下仍有观察机会。若狭窄门洞无法满足要求，应调整站位或改成明确的挑战交互。敌人的警戒同样受墙和关闭房门约束；听觉可引起搜索，但不允许隔墙开战。

普通怪物采用[怪物行为与多怪接战草案](07_迷宫怪物行为与多怪接战.md)的逐个实体判定：同一步的合法接触者与瞄准完成者共同参战，附近接触型怪物还需满足可见观察、预警完成及短路径等协战条件。未完成瞄准的射手不通过协战跳过预警，小队或房间归属也不能把关闭门后的怪物自动拉入战斗。挑战入口可以代表预设编组，但不能提前展示隐藏成员的位置。伏击与远程释放都不增加地图先手回合或入场伤害。

远程的射击遮挡独立于透视和通行：透明屏障可挡攻击，明确可穿射的低栏杆可在同一允许交战区内远程触发。瞄准期间双方必须可见，任一方失去视线即清空瞄准；不会让视野外或拐角后的攻击直接切入战斗。上述例外不改变地形记忆或地图信息边界。

已知敌人特征支持战前装备选择；换装继续遵守“非警戒可调整、警戒后只读”的候选规则。敌人离开视线不等于解除警戒，地图菜单也不清除追击状态。与普通敌人不同，关键挑战仍保留明确确认，隐藏其未获知的身份和具体技能。

## 6. 捷径、休息与回访形成持续进度

沿用现有资源草案：血量跨战斗保留，主动休息恢复并刷新普通敌人。休息点建议放在探索段落的支点，深入阶段主要通过捷径重新连接安全位置；不要求每个新房间或跨区域入口旁都设置休息点。

**捷径也是探索奖励。** 打开后应实际减少回程和再次挑战所需的路程或普通战斗。卡牌战斗的重试成本包含完整战斗时长，验收时同时统计路程、必经战斗数量和总耗时；如果打开捷径仍要重复打完原路线，应调整连接落点和敌人布置。

已解锁捷径、关键机关、宝箱领取和入口发现作为稳定探索进度保留。敌人刷新后，已探索区域仍只有地形记忆；需要重新接近才能观察敌人状态。一次休息不把全图改为当前可见。

建议回访由具体目标驱动：找到钥匙、取得适配装备、成长后挑战可选强敌，或从新位置理解旧场景的连接。视野内的一次成功观察也可以是收获，但重要支路仍需有可辨认的内容回报，避免反复遇到无意义空路。

区域内优先让捷径承担返回功能；快捷传送如后续加入，建议要求地点已实际到达并激活，不能凭远处看见休息点或获得区域传闻就传送。死亡仍沿用此前温和返回的候选方案；掉落回收、损失货币或减少血量上限未在本轮定案。

## 7. 示例：从陌生门后走回熟悉庭院

下图是设计者使用的完整结构图。玩家只随实际视野逐步发现其中内容。

```mermaid
flowchart LR
    A[入口庭院与休息点] --- B[关闭的木门]
    B --- C[L 形走廊]
    C --- D[守卫厅]
    D --- E[栅栏观察点]
    E --- F[机关与可选宝箱]
    F -->|从深处解除门闩| A
    F --- G[转角后的跨区域入口]
    E -. 透过栅栏认出庭院 .-> A
```

1. 庭院中只能看到木门及近侧墙面；门后传来拖拽声。玩家检查后开门，只露出走廊的直段，转角之后保持遮挡。
2. 玩家移动到转角逐渐看见守卫，决定准备后挑战或退回。胜利只改变遭遇状态，不自动揭开后面的房间。
3. 到达栅栏观察点，透过开口认出庭院的雕像，但仍无法直接走回；此时产生“这里就在入口旁边”的空间认识。
4. 深入机关处，从深侧打开门闩，形成返回庭院的捷径。玩家可以带着装备回去调整，或继续探索机关后的岔口。
5. 玩家再走过下一处遮挡才发现跨区域入口。发现捷径、取得宝箱与找到区域入口分别记录，不要求同时完成。

该例以“获得信息—理解位置—改变通路”为探索推进，风险和奖励仍与既有角色成长、装备构筑及卡牌战斗相衔接。

## 8. 原型验收与待定参数

先在一个包含关闭房门、L 形拐角、透视栅栏与单侧捷径的小区域验证，再扩展内容。以下全部为待执行检查。

| 场景／操作 | 预期结果 |
| --- | --- |
| 贴近关闭房门，移动镜头或悬停鼠标 | 房间形状、敌人、物品、名称与提示均不泄露 |
| 开门但不移动 | 仅揭示门洞可见部分；墙侧死角仍隐藏，不直接进入普通战斗 |
| 沿 L 形走廊移动，紧贴墙角 | 拐角逐渐揭示，无对角缝隙透视；普通敌人在接触前有可观察阶段 |
| 探索过房间后离开视距或关门 | 只保留已知地形与上次观察记录，动态敌人和实时状态消失 |
| 透过栅栏或上下层开口观察 | 只显示实际可见内容；不获得未走过的路线或地点激活状态 |
| 未知空间发出声音、使用声音文字提示 | 获得同等模糊程度的线索，不显示精确坐标或怪物清单 |
| 首次绕行并从深处打开捷径 | 能识别回到的旧地标，后续推进的路程或必经战斗明显减少 |
| 休息刷新或读档回访已探索房间 | 地形记忆保留；按当前位置与门状态重算当前视野，不保留旧动态可见性 |
| 查看完整地图、获得钥匙或远望地标 | 未发现内容继续遮蔽，不自动显示秘密门、全图路线或传送目的地 |
| 隐藏敌人显现、离开视线、战斗胜利 | 不隔墙触发；失去视线不清警戒；胜利不全揭房间；既有抽牌与资源回合规则不变 |

待通过原型确定：视距与过渡宽度、首次显现至接敌的空间和提示时机、可见地形的记忆粒度、照明是否参与视距、小地图形式、休息点间隔及捷径节省的实际重试成本。敌人感知、房门状态、地形记忆和存档恢复需要一致；视野外对象可以继续存在与活动，但不能通过显示或交互泄露其状态。
