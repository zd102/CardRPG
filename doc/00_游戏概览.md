已明确的方向：开发一款**以 RPG 角色成长和地图探索为主要乐趣的 2D 卡牌 RPG**，采用轻量化剧情。世界由多个区域组成，区域内是探索深度较高的箱庭式迷宫，区域之间采用不太复杂的网状连接，玩家需要在迷宫内探索发现通往其他区域的入口。角色采用无职业、属性加点决定装备资格、装备组成卡组的核心设计。开发采用 **Godot 4 稳定版（.NET）+ C#**；正式首发平台、世界观题材、战斗形式、具体数值与发行方式仍待确定。

## 1. 游戏一句话介绍

玩家在多区域大世界中探索箱庭式迷宫、寻找通往其他区域的入口，同时培养没有职业划分的角色，通过属性加点与装备选择形成卡组进行战斗。

### 世界与探索体验

- **角色成长与地图探索**是主要乐趣，卡牌战斗与既有的属性、装备构筑相衔接。
- **大世界由多个区域组成**，区域之间采用较简单的网状连接；区域内部提供较深的箱庭迷宫探索。
- **跨区域入口需要在迷宫内发现**，寻找入口本身属于探索过程。
- **探索采用有限可视范围与空间遮挡**，关闭的房门后、拐角遮挡处不可见，范围外保留神秘感；继续参考《黑暗之魂》三部曲的探索体验完善机制。
- **剧情采用轻量化设定**，为角色冒险和区域探索提供背景与动机。

定位依据见[产品定位与体验](01_游戏定位/01_产品定位与体验.md)，地图主规则见[地图探索与关卡结构](06_世界与关卡/02_地图探索与关卡结构.md)。区域数量、移动视角、地图生成方式、入口附加条件与回访方式仍待填写。

视野主规则及空间记忆、捷径、回访的建议见[视野遮挡与箱庭探索机制](06_世界与关卡/06_视野遮挡与箱庭探索机制.md)；具体视距与探索节奏待验证。

美术方向暂定为**类似黑魂的暗黑氛围基础，偏简约像素风**；具体配色、角色比例和像素规格见[美术风格与资源清单](09_美术音频与文本/01_美术风格与资源清单.md)，仍待打样确定。

### 已确认的核心规则

1. 角色没有职业划分。
2. 可分配属性为力量、敏捷、智力，加点决定能否满足装备的属性需求；力量提升血量、敏捷提升速度、智力提升元素抗性。
3. 每件已穿戴装备向卡组添加其对应的 x 张卡牌，合起来构成整个卡组。
4. 未穿戴武器时加入默认卡牌，避免卡组为空；即使防具等其他装备已提供卡牌，也按无武器条件加入。
5. x、默认卡牌种类与数量、属性需求的计算口径均待填写。

核心构筑路径：**属性加点 → 满足装备需求 → 穿戴装备 → 汇总装备卡牌 → 形成战斗打法**。

### 卡牌与默认战斗循环

- 行动卡消耗行动点，魔法卡消耗魔法点，具体费用按卡牌配置。
- 无特殊效果时，角色每回合开始抽 5 张（含首回合），回合结束丢弃所有手牌至弃牌区。
- 已使用卡牌进入弃牌区；需要抽牌而抽牌区为空时，将弃牌区全部洗回再抽。两区都为空时不抽牌。
- 规则明细见[卡牌分类](04_卡牌系统/01_卡牌结构与分类.md)、[费用规则](04_卡牌系统/04_费用目标与效果表达.md)及[牌区流转](04_卡牌系统/03_抽牌手牌与牌区流转.md)。

### 装备部位与贡献

角色可穿戴一件双手武器或两件单手武器，以及头盔、身体护甲、手套、鞋子各一件、戒指两件、护符 1～4 件（槽位随游玩进度解锁）。每件实际穿戴装备提供对应的 x 张卡牌，并有额外属性加成或者特效。

双手武器按一件装备计算卡牌贡献。具体部位约束见[装备部位与穿戴](03_装备系统/01_装备部位与穿戴.md)，护符解锁条件见[进度与解锁](07_奖励与经济/03_局内局外进度与解锁.md)，各装备的 x、数值与特效仍待填写。

### 属性体系摘要

- 可分配属性：力量、敏捷、智力。
- 基础战斗属性：血量、行动点、魔法点、速度、护盾值。
- 护盾默认在拥有者的角色回合开始时全部消失，特殊效果可另行规定；清除与其他回合开始效果的顺序待填写。
- 资源回合规则：行动点每回合开始恢复到上限；魔法点在回合结束时保留，下回合开始恢复固定数值，最多达到上限。具体数值见[资源抗性与生存](02_角色与属性/04_资源抗性与生存.md)，待填写。
- 三种物理类型：斩击、戳刺、打击，各有抗性与伤害加成。
- 五种元素类型：火、冰、雷、毒、暗，各有抗性与伤害加成。
- 成长机制：可分配属性达到一定数值后有额外效果。**力量达到 30 后额外提供物理抗性是暂定示例**，阈值、范围与数值尚未定案。

具体属性定义见[属性定义与计算](02_角色与属性/02_属性定义与计算.md)，加点与阈值见[等级加点与成长](02_角色与属性/03_等级加点与成长.md)。其他属性可以继续补充。

世界题材、具体冒险目标与剧情内容：待填写。

## 3. 核心体验与循环

### 3.1 设计支柱

详细定位见[产品定位与体验](01_游戏定位/01_产品定位与体验.md)。以下观察方式用于后续试玩，尚未验证。

| 原则 | 玩家会做出的具体选择 | 如何观察是否成立 |
| --- | --- | --- |
| RPG 角色成长 | 决定属性投入与装备搭配，形成战斗卡组 | 玩家能说明成长选择如何改变装备资格与打法 |
| 深入探索区域、理解世界连接 | 探索区域内部路径，寻找通往其他区域的入口 | 玩家能发现新的通路，并理解区域之间的连接关系 |
| 轻量化剧情 | 理解冒险动机后继续成长与探索 | 试玩检查剧情是否提供必要背景，且保持成长与探索为主要体验 |

### 3.2 玩家循环

1. 依据当前属性与装备选择构筑，形成战斗卡组。
2. 在区域内探索箱庭式迷宫，选择路径并应对遇到的挑战。
3. 通过角色成长与装备选择调整构筑；成长资源、装备来源和调整时机待填写。
4. 在迷宫内发现通往其他区域的入口，继续拓展探索范围；发现后的通行条件待填写。

成长与探索在过程中交织，以上不限定每次战斗后都成长或每次探索都进入新区域。失败代价、进度保留和单次冒险边界见[核心循环与玩家旅程](01_游戏定位/02_核心循环与玩家旅程.md)，仍待填写。

## 5. 填写方法与顺序

所有“待填写”都可以直接替换为你的结论。提示中的机制只是选项；未采用时写“不适用”及原因。尚未决定写“待决定”，不要把示例或备选方向视为已确认规则。

建议分四轮填写，不必一次填完全部文档：

1. **确定方向**：先填本页第 1～4 节，再补游戏定位、核心循环与首版范围。
2. **打通核心规则**：依次填写属性、装备穿戴与联动、卡牌构筑与效果、战斗流程与公式。用一组“角色＋装备＋卡牌＋敌人”手工走完一场战斗。
3. **补全可玩流程**：填写关卡、掉落、经济、成长与界面，走完“准备—挑战—奖励—调整构筑—保存—继续”的过程。
4. **准备实现与生产**：确认技术架构、配置、存档、资源清单、数值基准、开发任务与测试计划，再逐步增加内容条目。

模块文档顶部记录状态、负责人、更新日期和版本。建议状态按“待填写 → 草案 → 已确认”推进；实现与验证状态另在任务和测试记录中维护，避免将设计确认误认为功能完成。

## 8. 开始实现前的检查

这些是建议的设计检查项，需结合首版范围选择。

- [ ] 已明确玩家控制什么、如何行动、如何胜负。
- [ ] 已用具体数值解释属性、装备和卡牌如何共同决定结果。
- [ ] 已确认换装、抽牌、死亡、同时触发等核心边界规则。
- [ ] 已手工走通至少一个完整的最小可玩流程。
- [ ] 已定义首版内容数量和明确不做的功能。
- [ ] 已记录数据、存档、界面与资源的实现要求。
- [ ] 已为核心规则填写可复现的验收案例。
- [ ] 尚未确定且会阻碍实现的问题已有明确记录。
