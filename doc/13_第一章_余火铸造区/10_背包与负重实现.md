# 外环背包、仓库与负重实现

> 2026-10-13。[章节入口](01_章节总案.md) · [完整规则](../07_奖励与经济/02_背包仓库与遗留物.md) · [制作内容设计](09_携行制作与仓储扩充.md)

外环已接入实物库存、背包装备位、格位限制、地面遗留物与负重。**备用装备取消两件上限，装得下即可携带；穿戴及随身重量超过 20 kg 时，场景行动值翻倍。** 这是独立于格位的软性负重限制，不会禁止超重拾取或出发。

## 已接入的玩法

| 系统 | 当前行为 |
| --- | --- |
| 口袋与背包 | 无包 4 格；BP01／BP02／BP03 分别增加 8／12／16 格，不提供卡牌 |
| 占格 | 武器、身体、未装备背包 2 格；手部与外环任务物 1 格；材料每 10 件一格，U01 每 2 件一格 |
| 备用 | 没有件数上限，穿戴不占储物格；卸下物品要有位置，换小包容量不足则整个操作被拒绝 |
| 仓库 | 48→72→96→128 格；分类和陈列不额外生成库存 |
| 负重 | 穿戴、背包自身、随身材料／任务物／补给全部计重，仓库和地面不计重 |
| 场景行动 | 按开始时重量计算，超重普通行动 1→2，含噪声搜索 2→4，拦截同样计费；巡逻每次实际行动至多移动一次 |
| 免费操作与战斗 | 阅读、查看地图、合法换装、首次结果装包和撤离仍免费；战斗卡牌费用和行动点不翻倍 |
| 遗留物 | 搜索与胜利先生成原地点容器，可部分拾取；放下物品生成当前位置遗留物，同次离开／读档后仍可回取 |
| 撤离与失败 | 仓满余物保持安全随身；已登记出发装备受保护，其他随身实物失败丢失；地面普通物在远征结束重置 |
| 任务与制作 | 先计算扣物／扣料后的产物空间，不足不交付、不扣料；可以使用基地安全随身材料 |
| U01 | 免费出征份 0 或 2 件可选、占格且本趟结束清除；普通份可制作、拾取、留仓、带入和在区域使用 |

玩家按 **I → 物品与仓库** 取放物品，装备页选择背包和备用。工坊 **背包与仓储** 页提供背包制作、普通补给制作与扩仓。搜索结果自动打开拾取页；整批装不下时可按件选择，剩余物品留在原位。地图列出已发现的遗留地点，只能到现场取物。

重量使用整数克计算，界面显示 kg。铁锤 4 kg、铆钉护甲 6 kg、BP01 1 kg，加上 15 份各 0.6 kg 的废钢恰好 20 kg，不算超重；再加一份才触发。超重时放下重物的本次取放仍付双倍行动值，下一次行动恢复正常。

## 外环内容与完整章节的差异

现有七个地点没有 Q03～Q05，为使新增机制可以在当前版本完整体验，采用以下切片开放条件：BP01 开局可制作，BP02 在 Q02 后，BP03 在 Q02＋S01 后；W01 在 Q02 后，W02／W03 在 Q02＋S01 后顺序扩建。配方数量和成本沿用新增内容表。未来接入完整章节时需显式调整这些条件，不能把当前切片称为整章完成。

新增外环材料为 M07 再生织物、M08 净化药剂、M09 密封树脂、M10 承重构件。A03 工装残片给织物；A02 完整货箱附带织物与树脂；已修复 A05 提供药匣与旧货架。Q02 后的 A04 行李柜提供尚未持有的 BP01。首获材料按安全带回数量结清，部分领取不会复制整包首奖。

当前实现 U01，U02～U06 的战斗品与后续地区投放仍待接入。当前支持明确确认后放弃非任务实物；装备回收返料、收藏图鉴分离、地点内可调整摆放坐标、任意组合的取放预览，仍是后续设计。现阶段遗留物按“地点＋原物件容器”保存，用场景入口打开清单；换包不足时先放下或存仓，再换装。

仓库为已登记出发装备保留真实返还格位，避免放下装备后撤离造成仓库溢出。成功时先收回受保护的遗留装备，再释放未用预留并存放新收获；失败按原穿戴／备用位置恢复。留在身上的安全材料再次出发后重新承担风险。

## 存档与实现入口

`chapter1-inventory-v2.json` 为新存档，`Stock` 中的唯一实例保存数量、容器、来源、登记、校准与免费份身份。`Owned/Loot/Backups`、材料数组及补给数量由实际库存派生，读档校验二者一致，拒绝重复实例、非法位置和普通超容量存档。

首次启动可从 `chapter1-outer-ring-v1.json` 迁移，原文件保留；更早的 `expedition-v1.json` 不受影响。旧库存超容量不丢弃，保留原位置并标为待整理，达到合法容量后再出发。进行中的旧远征可以完成，但不能增加超额占用。每次有效操作保存失败会恢复该操作前的状态，保留错误提示。

- `ChapterSession.Inventory.cs`：容量、重量、取放、制作、仓储、归属与结算。
- `ChapterSession.InventorySave.cs`：旧档迁移、实例与容器校验。
- `ChapterSession.World.cs`：场景行动成本与原位奖励生成。
- `ChapterGame.InventoryUi.cs`：物品取放、重量提示、背包制作与扩仓界面。

## 角色与库存界面更新

装备页和行前整备用武器、身体、手部、背包四个部位展示穿戴；可选装备以图鉴格排列，选中后显示重量、位置、供牌和操作。库存分为随身格位、仓库／地面格位、选中详情三个区域，同类物品按实际堆叠规则占格，双格装备有独立续格。来源批次仍保留，详情中的单件／整批操作不改变物品归属规则。

C 或顶部角色图标打开全览页：显示生命、行动、魔法、护盾、补给、负重、共鸣、穿戴和完整卡组。非战斗显示穿戴构筑；战斗按实际手牌、抽牌堆和弃牌堆合计副本，并展示本场装备来源。台架试用显示借用卡组，实际负重仍按真实库存计算。点部位或库存按钮可进入管理页，Esc 返回全览。查看页面不会消耗行动、改变牌序或随机状态。

界面变更未修改库存规则或存档格式。构建无警告与错误；60 项规则回归全部通过。真实输入检查覆盖 1100×760、1280×800、1600×900、四部位布局、格位数量与规则一致、完整卡牌副本、战斗页只读、键盘焦点、嵌套返回，以及穿戴、备用、拾取、放下和存取流程。源码无头验证与更新后的 Windows 导出包均通过，后者使用 ANGLE 实际渲染，并检查了角色、装备、库存与整备截图。

导出仍为 `artifacts/Expedition/CardRPG-Expedition.exe`；本次截图及导出日志作为验收记录保留在 `artifacts/character-ui-verification`。构建使用原有输出目录，未删除已有构建文件或前次验证产物。
