# 热门游戏对照与 23 张截图优化建议

日期：2026-10-16。审查对象是上一版可运行包随附的 **23 张原始截图**，包括普通、紧凑、选牌预览和不同尺寸的战斗画面。未把此前设计文档作为合理性依据；只在核实预测条件和结算排版时查看了当前实现。本轮产物是建议，游戏代码未修改。

**建议下一轮优先建立稳定的物品操作区和一致的状态表达。** 当前版本的插画、出发页分区、卡牌增减说明已有可用基础，但很多操作仍套用同一种大纸板、长按钮和全局导航。其结果是：页面看起来内容很多，真正需要比较的物品、费用和后果却分散或被挤到滚动区。熟练操作所需的功能已经存在，仍需要缩短寻找和执行路径。

[打开逐图审查与建议布局](../media/ui-reference-review-20261016/index.html)。页面包含全部 23 张原图、按优先级筛选的意见、官方参考图和三组信息结构草图。草图中的数字与排列是待验证的建议，并非已实现效果。

## 1. 先修正三类会影响理解的实际问题

| 优先级 | 已确认问题 | 对玩家的影响 | 建议 |
| --- | --- | --- | --- |
| P0 必须修正 | 结算图中“封装继电器 ×1”逐字竖排 | 核心收获无法正常扫描，成功反馈被破坏 | 修复物品行横向布局；首屏横排展示主要收获、世界变化和下一步 |
| P0 必须修正 | 选牌预览显示护盾 0→4，结束回合区却显示护盾抵挡 0、生命 42→36 | 同屏混合了“出牌后”和“未出牌”的两种预测条件 | 所有预览明确标出计算条件；比较当前结束与出牌后结束时使用同一规则副本 |
| P0 必须修正 | 准备页“剩余空间 3/4”与拾取页“背包空间 1/4”分子含义不同 | 容量在跨页时需要重新解读，容易误判断是否装得下 | 统一“已用 1/4 格 · 空余 3 格”；操作后值另列 |
| P1 优先改进 | 地图提示“从场景出口移动”，同时存在可执行的前往按钮 | 玩家不能确定地图是否可直接操作 | 统一文案为可执行的一站移动，并区分最终目的地与下一站 |
| P1 优先改进 | 物资对照表滚动后列标题和展开批次的父名称离开视野 | 比较时失去容器方向与物品身份 | 表头固定；展开批次保留父物品标识 |
| P1 优先改进 | 继电器与事件补给使用相同物品形象 | 任务物与恢复品的识别相互干扰 | 优先补齐这类高频物品的独立图标 |

P0 对应明确的显示缺陷或核心语义歧义；P1 是高频操作摩擦；P2 是可保留现有结构、随后精修的部分。这里没有把截图中的观感问题伪装成已测得的玩家耗时。

结算竖排可由 `ChapterGame.OverviewUi.cs` 的物品行布局定位。战斗右侧当前使用 `Session.Preview(s => s.EndTurn())`，左侧则使用待出牌结果，确认了两处预测的条件不同。问题并非证明某一数值算错，而是界面没有让玩家分清它们的含义。

## 2. 从两款游戏借鉴什么

| 参照对象与可观察做法 | 在本项目中的应用 | 适用边界 |
| --- | --- | --- |
| 鸭科夫拾取图：左侧携带区、右侧容器同时出现，容量与负重靠近携带物 | 拾取、腾空间和仓库转移使用相同的空间关系，减少反复切页 | 当前物品占格按规则计算，不能让“一张目录图块”冒充“一格实际容量” |
| 三角洲仓库图：穿戴与库存分区，整理动作位于稳定区域 | 管理页固定穿戴/随身、库存、选中详情的关系 | 参考分工；不引入游戏没有的市场价格、弹药等级和背包拼格玩法 |
| 三角洲准备图：武器、防护、补给检查集中在一页 | 预设、当前装备、补给、容量与出发条件集中检查 | 本项目最重要的装备后果是卡组变化，应给它更高权重 |
| 三角洲属性详情图：按属性维度进入详细数据 | 改装先显示伤害、护盾、费用、替换份数的差值，完整规则按需查看 | 不需要复制射击游戏的伤害距离曲线或一整套复杂枪械数值 |

参考来自[鸭科夫当前 Steam 商店媒体列表](https://store.steampowered.com/app/3167020/Escape_From_Duckov/?l=schinese)及其[拾取原图](https://shared.akamai.steamstatic.com/store_item_assets/steam/apps/3167020/ss_ffb859764420f62c612287f011361749a06b6432.1920x1080.jpg)，以及 Garena 于 **2026-02-20** 发布的[三角洲官方 Operations Mode 101](https://deltaforce.garena.com/en/news/system/RMDWVM)。三角洲图中的红框、绿底文字是教程标注，不作为常规 UI 设计元素。

查阅日期代表资料获取时间，不代表素材对应当天最新客户端。鸭科夫商店仍含标注 `trial version` 的历史截图，这些仅在来源记录中保留，不用于论证当前客户端功能。具体快捷键、交互时延和玩家效率没有通过实际游玩竞品验证。

两款游戏的可取之处是对象分区与操作连续性。大量格子、缩写、小字以及多层成长菜单也可能增加学习成本；热门程度不能替代对本项目的适用性判断。**本项目应突出“装备改变卡组、搜刮影响撤离、行动增加压力”这三条关系。**

## 3. 下一版按四类任务组织界面

### 场景探索与拾取

场景保留版画美术和热点，但出口、物资、任务、战斗采用稳定的形状与位置规则。当前任务目标有独立标记，其他热点用短名称；聚焦时提供完整作用与代价。由于本项目通过点击热点操作，不能照搬射击游戏“走近后才显示交互”的方式，也不能要求新手逐个悬停才能发现可操作物。

拾取采用容器面板，随身物品与目标物同时可见。单件物资不需要占据大幅居中弹窗；物品行直接呈现“是什么、为什么需要、会占多少、这次是否免费”。免费窗口结束条件属于会影响操作成本的信息，应该靠近拿取和返回操作。

背包满时，在相同区域内展开取舍，而不是换成四段说明与四个同名按钮。候选表显示用途、释放格数和重量变化；任务物明确标识。选择放下后显示实际结果，再提出下一次拿取。**放下和拿取仍分别消耗真实行动，巡逻等事件发生后必须重新核算，不能自动串行承诺交换完成。**

### 营地管理与整备

以 1280×800 为原型基准，尝试左侧约 220 像素的穿戴/随身区、中间库存区、右侧约 300 像素的详情区。尺寸只是起点；窄屏将详情停靠到底部或按需展开，穿戴与库存之间的相对关系不变。左侧空背包不应持续挤压仓库清单。

搜索、分类、排序和常用整理放在固定工具栏。物品清单以名称、数量、用途标记和必要状态为主体；批次、完整属性和详细规则在选中后展开。批量模式在原位替换工具栏，不把一排排控件插到列表上方。原型验收目标可设为：**1280×800 普通字号下首屏至少 8 行核心物品信息**，再根据大字与长名称情况调整；不能通过缩小主要文字达成这个数字。

当前容量与预览容量分开：容器标题始终表示实际库存，选中物品的“带入后 2/4 格、负重 +1 kg”靠近操作按钮。界面用“物品”“数量”“保留随身”等玩家概念；状态相同的同类材料聚合显示，任务保护、免费补给、登记状态等不同的实物在需要时可展开区分。

整备页把预设、装备、补给和出发集中在同一工作区。初始工具应显示代表卡与费用类型；熟练玩家可快速调用预设，再看缺项或变化。角色页展示完整卡组，装备选择时强调贡献关系；换装直接给出“移出哪些卡、加入哪些卡、费用有什么变化”，保持当前已有的这项优点。

### 战斗决策

保留敌方意图常显、目标附近生命变化和出牌预演。底部建立连续的资源—手牌—回合操作区，限制最大宽度，避免在宽屏上把资源和结束回合推到两端。窄屏优先减少外围导航与重复教程，为牌面保留宽度。多手牌应有可控的浏览方式，不能无限压小牌面。

预览需要明确的状态条件：

| 显示区域 | 未选牌 | 选牌但未执行 |
| --- | --- | --- |
| 实际资源 | 当前行动点、魔法、护盾 | 当前值仍可辨认，另显示出牌后值 |
| 目标 | 当前生命与护盾 | 标明“打出后”的预计变化 |
| 回合预测 | 现在结束回合的结果 | 标明“现在结束”和“打出后立即结束”的差别，或明确切换为后者 |
| 主操作 | 选牌或结束回合 | 确认打出；取消恢复当前状态 |

本例“获得 4 护盾、敌方攻击 6”可用于验证条件表达；实际预测必须通过游戏规则模拟，不能在 UI 中简单用减法代替击杀、被动和多目标结算。选牌后点击结束回合是否放弃待出牌，也应有一致、可理解的行为。

新手保留“选牌—目标—确认”的可撤销路径；熟练玩家继续使用已有拖放与快捷操作。新增教程只在首次或相关情境出现，之后可从帮助回看。风险提示只在确有损失或不可逆后果时加强，避免每张普通牌都追加弹窗。

### 事件、任务与结算

故事页的正文、插画和继续按钮已经形成稳定结构，宜保留。事件选择保持并排比较，整卡可选，选中标识与键盘焦点明确区分。共同的规则放在选项附近；一次性选择仍需确认。

任务详情先呈现下一步、地点、缺少条件和奖励。追踪/交付成为当前主操作；地图定位紧邻地点，固定入口和更多操作降为次级。结算首屏则回答“得到了什么、世界发生了什么、接下来能做什么”。已经装备或完成的状态应结束比较，避免 `12→12` 和重复穿戴按钮继续暗示还有步骤未完成。

## 4. 视觉与操作规范应一起收敛

| 项目 | 建议规则 |
| --- | --- |
| 导航 | 场景、管理页和事件弹窗各有适合的导航层级；同一功能名称保持一致，密度切换不占用一级导航位置 |
| 容量 | 始终使用已用/总量；空余量单列；当前值与操作预览明确区分 |
| 行动术语 | 探索代价写区域压力变化；地图再写移动几站；战斗使用行动点。数值来自实际预览，不硬编码示例数值 |
| 字体 | 先以正文 16、区块标题 20、页面标题 28 三档试排；次要元数据可更小，大字模式保持主要信息完整 |
| 色彩 | 深绿用于主操作，选中使用边框和勾选，红色保留给损失/危险，提示带明确文字；状态不只靠颜色 |
| 边框与纹理 | 保留纸色和版画风格，减少反复嵌套的同等强度边框；装饰花框避开高频数字、工具栏和日志 |
| 图像 | 优先解决补给/任务物混用、背包规格难辨、卡牌类型难辨；动作插画保持可读构图，避免任意裁成长横幅 |
| 操作距离 | 选中物、变化预览、主要操作尽量相邻；确认、取消、返回保持一致位置和含义 |
| 熟练路径 | 安全区支持快捷转移、批量、保留标记和撤销；沿用已有按键映射，不强迫重新学习 |
| 信息展开 | 常用整理和比较直接可达；完整规则、来源矩阵、历史记录按需查看，偏好按页记忆 |

两类玩家共享对象位置与操作名称。首次说明增加理解辅助，紧凑布局减少重复信息和非必要间距；不要根据游玩次数擅自移动按钮或隐藏功能。搜索输入、数量输入和全局快捷键应有清楚的焦点边界。

## 5. 实施顺序与判断标准

1. **修正 P0 表达。** 结算不竖排，容量含义统一，战斗预测标出条件；同时处理地图旧提示。先恢复信息可信度。
2. **重组背包—拾取—腾空间。** 共用容器、物品、详情和动作的关系，验证空背包、大库存、满背包与任务物保护。
3. **重组准备—换装—改装—制作。** 预设可直接调用，核心差值不依赖额外弹窗，完成后显示稳定状态。
4. **收敛场景 HUD 与战斗工作区。** 处理热点优先级、宽窄屏间的相对位置、资源符号和卡牌类型识别。
5. **补足高价值图标与反馈。** 在信息结构确定后补补给、任务物、背包轮廓和必要的状态反馈，避免用新插画掩盖布局问题。

真人验证可先安排两组各 3–5 人：未接触游戏的新玩家，以及已熟悉当前章节规则的玩家。观察同样的任务：首次准备出发、拾取继电器、满包取舍、整理并保留补给、比较换装、预测回合损失、交付任务。记录完成时间、误操作、求助、开关面板次数与滚动次数；这些是待采集指标，不是本轮已测结果。

设计验收应同时检查结果正确与理解正确：新手能否在第一次操作前说明后果；熟练玩家能否在固定位置完成连续操作；取消与返回是否保留选择、筛选和滚动状态。后台自动化与截图检查继续覆盖尺寸、字号、拖放、焦点和失败路径，不能以“按钮存在、测试通过”替代逐图阅读。
