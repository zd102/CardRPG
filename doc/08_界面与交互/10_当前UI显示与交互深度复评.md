# 当前 UI 显示与交互深度复评（2026-10-16）

当前 UI 的核心操作链路已经比较完整，具备继续验证玩法的基础；**信息布局和阅读体验仍有明显问题，尚不能因为 204 项功能已实现就判定整体合理。** 最突出的问题是：局部文字布局失效、管理页辅助控件挤占内容、战斗说明区占地过大，以及小窗口／大字号只局部适配。

美术方向值得保留：旧铁路、木刻场景、纸色、墨绿和朱红已经形成辨识度。下一轮应优先修正阅读与决策空间，让玩家更快理解“对象是什么、会发生什么、下一步做什么”。

## 4. 当前布局为什么仍显得重

**信息量和可比较对象数没有同步增长。** 同一屏增加筛选、模式切换、批次、固定、材料计划、回执后，很多功能各占一行或一块固定区域。结果是“可做的事很多”，但“当前要读的物品和牌显示得少”。

**管理、战斗、剧情沿用了相近的面板思路。** 管理可以容纳工具栏，战斗需要紧凑的对象与后果关系，剧情需要保证正文。对三种场景使用类似的大纸板加滚动区，形成了不同的问题：战斗留白多、库存遮挡多、剧情正文少。

**控件尺寸在变，内容布局没有完整跟着变。** 大字扩大了正文，却没有同时扩大紧凑装备行；部分按钮与数值仍固定。自动验证看到外框都在屏内，仍不能判断文字是否越界。

| 画面观察 | 量化／可复核事实 | 设计含义 |
| --- | --- | --- |
| 战斗未选牌 | 1280×800 下，预览板 1084×160，约占屏幕 16.9%；旁边预测板另占约 2.1%。尺寸由当前布局代码计算，不含边距 | 这里的面积预算需要由选中状态控制 |
| 物品提示 | 标准多行提示样例约 540×300，相当于 1280×800 的 15.8%；内容只有几行 | 应按实际说明长度与是否主动固定分配空间 |
| 仓储大字与穿戴摘要 | 1100 样例可用浏览高度约容纳一行三件，下一行只露一部分；左侧仍有大空区 | 应压缩外围工具，调整空容器空间，而非进一步缩小字体 |
| 角色卡组 | 1280 样例首屏约五种完整牌行，1100 约四种；总牌数 10 并不代表有 10 种牌 | 要用同一构筑的完整可见牌种衡量密度，不能只看总牌数 |
| 剧情 | 批量交付截图的正文区首屏只容下人物／标题，故事正文未出现 | 有滚动条不等于首屏阅读合理 |

这些是特定夹具与状态下的观察，不是全部玩家平均值。列表中滚动到一半的条目被裁切属于正常行为；本报告没有把所有“截了一半的行”都算作 bug。B01 的窄名称列、B02 的条目外溢与 B03 的首屏正文缺席有具体代码和截图依据。

## 6. 逐项问题、建议与验收

下面的建议均为本轮评审结论，**尚未实施到游戏**。所有问题都附当前版本截图或实现依据；涉及玩家行为的推断已明确标注。

### B01 · 自定义装包的物品名被挤成单字竖排

**Critical · P1 · 拾取**　[当前截图](../media/ui-audit-20261016/completion-pickup-plan.png) · [实现位置](../../game/Scripts/ChapterGame.InventoryFlows.cs#L42)（ChapterGame.InventoryFlows.cs:42）

1280×800、标准字号下，左栏的废钢、导能线被挤到极窄位置；数量框紧贴并遮挡名字，栏内却有大量闲置宽度。

影响：在决定装入和留下哪些物品时，玩家难以把数量与物品对应。

建议：使用有明确列宽的“物品｜本次数量｜优先级”行；名称列扩展，数量框保持紧凑；不要用不扩展的自动换行 Label 承担名称列。

验收：标准与大字号都可同时读到完整物品名、本次数量和优先级；长名称至多两行，不能与数量控件相交。

### B02 · 大字号穿戴摘要的名称越出条目

**Critical · P1 · 适配**　[当前截图](../media/ui-audit-20261016/rework-1100-150-prepare.png) · [实现位置](../../game/Scripts/ChapterGame.CharacterUi.cs#L11)（ChapterGame.CharacterUi.cs:11）

1100×760、150% 字号下，“检修工具手套”换行越出手部卡片，挤到下一件装备区域；装备比较页也出现同样现象。

影响：部位和名称的归属变得不清楚，大字设置反而损害阅读。

建议：让紧凑装备行高度随字体和实际行数增长；窄屏改为横向摘要或收起非当前部位，不能只扩大文字而固定 68 像素卡片。

验收：四个槽位的名称与图标均在自身条目内；完整名称可见或有明确省略与可访问详情，不能借相邻条目的空间显示。

### B03 · 批量交付剧情首屏没有正文

**Warning · P1 · 剧情**　[当前截图](../media/ui-audit-20261016/completion-batch-story.png) · [实现位置](../../game/Scripts/ChapterGame.Panels.cs#L29)（ChapterGame.Panels.cs:29）

标准尺寸下，剧情窗口被标题、返回来源、人物和两个按钮占据；“灯又亮了”的正文在首屏完全落到滚动区下面。

影响：玩家最容易看到的是继续和停止操作，可能未读到剧情就离开。

建议：为剧情正文保留最低阅读高度；人物标题与正文分配空间，批量停止改成次级控件。窗口高度应计入所有固定区而非仅按正文长度估算。

验收：1280×800 标准字号首屏至少出现两行正文；1100×760 大字仍有完整正文行和清晰滚动提示，继续按钮不代替阅读区。

### B04 · 材料成本表的表头与数值对齐方式不一致

**Warning · P1 · 制作**　[当前截图](../media/ui-audit-20261016/management-material-recipe.png) · [实现位置](../../game/Scripts/ChapterGame.WorkspaceUi.cs#L122)（ChapterGame.WorkspaceUi.cs:122）

“拥有／消耗／剩余”表头左对齐，宽列中的数字右对齐；数字靠近下一列表头，改装页尤为明显。

影响：读成本时需要反复追踪列边界，可能把拥有量与消耗量看错。

建议：数值列的标题和数字使用同一右边界，限制列宽；材料列扩展，补充轻量行分隔。

验收：不移动视线到下一列就能对应标题与数值；同一行清楚读出“拥有 12，消耗 6，剩余 6”。

### B05 · 补给缺料以不成立的减法和笼统提示表达

**Warning · P1 · 制作**　[当前截图](../media/ui-audit-20261016/management-supply-quantity.png) · [实现位置](../../game/Scripts/ChapterGame.StorageCraftingUi.cs#L62)（ChapterGame.StorageCraftingUi.cs:62）

没有净化药剂时显示“0 − 1 → 0；扣仓库 0 / 随身 0”，随后只提示“材料或成品空间不足”。执行按钮确实禁用。

影响：规则没有错误执行，但界面没有明确指出缺哪件、差多少，且公式看似已经扣完。

建议：缺料直接显示“净化药剂：拥有 0／需要 1／缺 1”；分别列出材料、地点、产物容量等实际阻塞原因，并提供已知来源入口。

验收：玩家无需手算即可说出当前唯一或全部阻塞；没有材料时不展示为合法扣除后的余量。

### B06 · 轻量悬浮说明变成大型操作窗口

**Warning · P1 · 阅读**　[当前截图](../media/ui-audit-20261016/inventory-full-pockets.png) · [实现位置](../../game/Scripts/ChapterGame.GraphicUi.cs#L43)（ChapterGame.GraphicUi.cs:43）

管理页多行提示通常占 540×300，只有少量说明时仍保留大空白和固定／对照／关闭按钮。库存、装备和 720 截图均可见遮挡。FocusEntered 立即显示，鼠标离开但对象仍有焦点时可能继续保留。

影响：为了读一件物品，会挡住邻近候选或容器，打断比较与拖动。

建议：普通提示按内容收缩，先给名称、用途和一句关键后果；固定详情才展开工具栏。悬浮、键盘聚焦、主动固定分别管理生命周期；同一张牌避免同时出现两套阅读层。

验收：短提示不遮住当前主操作或下一候选；移入可继续阅读、Esc 可关闭；键盘用户仍能主动固定详情。

### B07 · 未选牌的预览区常驻占用过多战场

**Warning · P1 · 战斗**　[当前截图](../media/ui-audit-20261016/04-battle.png) · [实现位置](../../game/Scripts/ChapterGame.BattleUi.cs#L133)（ChapterGame.BattleUi.cs:133）

1280×800 下，卡牌预览区固定为 1084×160，仅此一块约占全屏 16.9%；未选牌时只放两行操作说明。右侧还另有 136×160 回合预测，敌人图像在小窗口明显缩小。

影响：视觉焦点落在空说明板和功能按钮，而敌人、意图、手牌之间的联系变弱。

建议：未选牌时将预览收成短条，选牌后展开结果；回合预计失血贴近结束回合按钮；把行动／魔法与手牌放在更近的区域，日志和排序改为次级入口。

## 7. 交互链路的总体判断

| 玩家任务 | 当前合理之处 | 当前仍需改进 |
| --- | --- | --- |
| 第一次整备出发 | 目的地有明确部署按钮，补给和出发容量有预览 | 初始工具选择、装备摘要与出发清单分散；起步阶段不需要同时理解全部专业视图 |
| 探索与阅读 | 阅读地图、卡组、说明不推进时间；出口有形状区分 | 关键任务物可更明确，采集／战斗入口的后果应在对象附近易读 |
| 战斗出牌 | 选牌→目标→确认与拖动均可用；可以取消；结束回合有生命预测 | 预览常驻面积、资源距离、自身牌拖动落点与回放状态需更直观 |
| 地面拾取 | 免费窗口、有费用取放、腾空间和部分拾取都有规则边界 | 自定义数量页的名称列必须先修；应让“本次装入／留在原位”成为真正可比较的内容 |
| 营地整理 | 同屏两端、数量、保护、快移和撤销已经具备 | 批次与容量单位、悬浮遮挡、菜单过大、表头滚走降低效率 |
| 装备／卡组／改装 | 清楚区分穿戴与备用，能查看供牌来源和改装差异 | 主差异应在第一屏，完整规则与重复字段按需展开 |
| 制作与材料计划 | 计划不直接制作，成本和实际来源可查 | 表格对齐、缺口与全部阻塞条件需要统一表达，不能用笼统错误提示 |
| 任务交付与剧情 | 每项重新校验、保存，剧情可中断队列，失败只撤回本项 | 正文阅读区和队列完成态需要重做呈现 |
| 撤离／失败／恢复 | 收获、丢失、永久变化、回滚有说明 | 高光收获值得更清楚地展示；终态按钮应准确表达下一步 |

固定对照快照目前会明确提示“只读、不是当前执行结果”，这一点是正确的。若跨对象或跨系统查看，建议进一步显示来源、对象类别和固定时点；本轮没有证据表明它会改写真实规则状态，因此没有把它列作执行错误。
